# AI Knowledge Assistant

Upload documents, then ask questions in plain English. Answers are generated by a **local LLM (Ollama)** from
passages retrieved with **FAISS semantic search**, and every answer links back to the **file and page** it came from.
Nothing leaves your machine.

```
React (Vite)  ──►  FastAPI  ──►  extract → chunk → embed (Ollama) → FAISS index
     ▲                │
     │  SSE stream    ├──►  retrieve top-k chunks ──► prompt ──► Ollama LLM (streamed)
     └────────────────┘
                      └──►  PostgreSQL: documents, conversations, messages (+ sources)
```

## Features

- Upload PDF, DOCX, TXT and Markdown (drag and drop, multiple files)
- Background indexing with live status (processing / ready / failed)
- Semantic search over all documents, or scoped to the ones you tick
- Streaming answers with clickable `[1]` citations, source snippets and "open page N" links
- Follow-up questions work: the question is rewritten into a standalone query before retrieval
- Conversation history and document metadata stored in PostgreSQL
- FAISS index persists to disk; deleting a document removes its vectors
- Health banner tells you if Ollama is down or a model is missing

## Prerequisites

| Tool | Version |
|---|---|
| Python | 3.10+ |

| Docker (for PostgreSQL) | any recent |
| [Ollama](https://ollama.com) | any recent |

## Setup

### 1. Models (Ollama)

```bash
ollama pull llama3.2          # chat model (~2 GB)
ollama pull nomic-embed-text  # embedding model (~270 MB)
ollama serve                  # skip if Ollama already runs as a service
```

### 2. Database

```bash
docker compose up -d          # PostgreSQL on localhost:5432
```

Tables are created automatically when the API starts.

### 3. Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env          # edit if you changed ports or models
uvicorn app.main:app --reload --port 8000
```

API docs: http://localhost:8000/docs

### 4. Frontend

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173.

## Configuration (`backend/.env`)

| Variable | Default | Notes |
|---|---|---|
| `DATABASE_URL` | `postgresql+psycopg2://postgres:postgres@localhost:5432/knowledge_assistant` | |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | |
| `LLM_MODEL` | `llama3.2` | Any chat model you have pulled (`mistral`, `qwen2.5`, `llama3.1:8b`…) |
| `EMBEDDING_MODEL` | `nomic-embed-text` | **Changing it requires re-uploading documents** (vector sizes differ) |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `1000` / `200` | Characters |
| `TOP_K` | `5` | Passages sent to the LLM |
| `MAX_UPLOAD_MB` | `25` | |

## API

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/documents` | Upload one or more files (indexed in the background) |
| `GET` | `/api/documents` | List documents and status |
| `GET` | `/api/documents/{id}/file` | Original file (supports `#page=N`) |
| `DELETE` | `/api/documents/{id}` | Delete file, metadata and vectors |
| `GET/POST` | `/api/conversations` | List / create conversations |
| `GET/DELETE` | `/api/conversations/{id}` | Fetch with messages / delete |
| `POST` | `/api/conversations/{id}/messages/stream` | Ask a question (SSE: `sources`, `token`, `done`, `error`) |
| `GET` | `/api/health` | Ollama reachability and missing models |

## Tests

```bash
cd backend
pip install pytest reportlab
pytest -q
```

The test suite runs the real upload → chunk → FAISS → retrieve → stream → delete flow using SQLite, a fake
embedder and a fake LLM, so it needs neither Ollama nor PostgreSQL.

## Project layout

```

  main.py                FastAPI app, CORS, /api/health
  config.py              Settings from env
  models.py  schemas.py  SQLAlchemy tables and Pydantic models
  routers/documents.py   Upload, list, serve, delete
  routers/chat.py        Conversations and streaming Q&A
  services/extraction.py PDF (per page), DOCX, TXT, MD
  services/chunking.py   Page-aware recursive splitting
  services/vector_store.py  FAISS index with metadata filtering
  services/rag.py        Query rewriting, prompt, streaming generation
  services/ingestion.py  Background indexing job
frontend/src/
  App.jsx                State and orchestration
  api.js                 REST client + SSE stream reader
  components/            Chat, Message, Sources, Library, ConversationList
```

## Limitations and next steps

- **Scanned PDFs** have no text layer, so they fail with a clear message. Add OCR (`ocrmypdf` or Tesseract) in `extraction.py`.
- DOCX and TXT have no page numbers, so their citations show the filename only.
- **No authentication.** Add per-user ownership to documents and conversations before exposing this beyond localhost.
- FAISS runs in-process, so use a single API worker (`uvicorn` without `--workers`).
- Ideas: hybrid BM25 + vector search, a reranker, Alembic migrations, Docker images for the API and UI.
